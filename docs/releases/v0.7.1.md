# v0.7.1 · Windows 触摸兼容修复版

针对另一台触摸设备上「音乐关不掉／文字闪回」「听陈叔收尾直接返回首页」的反馈修复。保留v0.7.0的全部内容、两首音乐及玩法。

## 下载与运行

下载 Assets 内的 **13-Hongs-Manager-v0.7.1-Windows-x64.zip**，解压到新文件夹。在反馈问题的设备上优先双击 **启动兼容模式.cmd**；普通电脑继续使用「启动游戏.cmd」。F11可切换全屏。

完整包包含便携Godot、所有素材和两首音乐，无需另装Godot或Python。旧版v0.7.0仍保留在历史Release中。

## 排查结论

本地通过原生触摸事件后紧接鼠标事件，复现了两个症状：

1. 音乐按钮先切到关，补发鼠标点击又将其打开。
2. 「听听陈叔的收尾」进入结尾页后，补发点击落在几乎同位置的「合上账本」按钮上，直接结束。

这是已确认的游戏输入处理漏洞；现场触摸驱动是否发出了同样的事件，需要该设备回测或日志确认。当前证据不能认定为Snapdragon处理器或音频硬件故障。

## 修复内容

- 原生触摸附近短时间内的鼠标补发事件统一拦截；反向的鼠标／触摸重复激活也去重。
- 全部按钮统一加入转场保护，同一个按钮的触点抖动不会连续触发。
- 音乐关闭同时暂停流、静音专用音乐总线并将输出归零。关闭期间调音量不会重新出声；开启时恢复所选音量与进度。
- 兼容模式保持Compatibility渲染，限制30帧并延长补发事件拦截窗口到1.2秒，记录本地事件诊断。
- 正常版本也包含这两个输入修复；兼容模式提供额外运行参数。

## 回测重点

1. 打开声音设置，轻点一次「背景音乐 开」。文字应稳定为「背景音乐 关」，音乐停止；调音量仍保持关闭。
2. 过一秒再点一次，音乐从原进度恢复。
3. 完成一单，轻点「听听陈叔的收尾」。收尾画面应保持显示，下一次主动点击「合上账本」才返回首页。
4. 检查取工具、音量拖动、继续经营和再做一单仍可操作。

兼容模式的引擎日志为 `artifacts/compatibility.log`；按钮来源、拦截原因及系统版本写入 `runtime-data/` 下的 `sessions.jsonl`。日志本地保存并轮换，不自动上传。

## 验证边界

在本机注入相同事件顺序，检查触摸→鼠标、鼠标→触摸、延迟补发、边沿交错、取消触摸、快速重复触摸和正常后续操作。成品ZIP会重新解压，运行音乐、角色、工序与兼容专项，再以30帧进行实际GPU验证。

用户提供的系统为Windows 10 21390.2025，处理器为Snapdragon 860。微软将21390列为Insider Preview构建；本次没有这台设备可供实测。本包仍为x64程序，在ARM Windows上依赖系统已有的x64运行支持，**不是ARM64原生包，也不宣称已通过该设备验收**。此前该设备能运行v0.7.0，因此先针对已复现的输入漏洞修复。
