# 后续工序手势设计方案

状态：基于 v0.10.0 整理的已确认设计。第一批六道工序、七个动作及操作衔接已在 v0.11.0 实现，详见 [实现说明](v0.11工序手势与操作衔接.md)；第二批交接与航行仍为后续提案。

## 1. 设计目标

让游客看见道具就能理解怎样操作，每个手势对应一个清楚的工序动作。支持鼠标左键与单指触摸，完整一局仍以3—5分钟为体验目标。

v0.10.0已有：轻晃茶杯、绕盘翻茶、沿路封绳、三轮箱组拖拽。本轮优先补齐其他六道工序，并为已有封绳步骤补一个合盖动作。

以下秒数是设计目标，包含短动作反馈，不是完成倒计时，也尚未经过游客测试。新增必经操作替代原点击与等待；整段工序的停留时间需在实现后重新测量。

## 2. 优先补齐的六道工序

| 当前步骤 | 推荐手势 | 场景反馈与完成条件 | 目标用时 |
|---|---|---|---|
| 看叶形：摊叶观察 | 按住茶样，从中央向左、向右各拨开一次，允许分两次落指 | 茶叶随轨迹散开，露出完整叶与碎叶。覆盖两处宽观察区域后完成，梁老板给出当前茶样线索 | 3—4秒 |
| 辨干湿：轻捻茶叶 | 按住一撮高亮茶叶，做两次短距离往返揉动 | 局部放大，茶叶随手指捻动；完成后根据现有观察线索表现干爽或潮软，并显示一句结果 | 3—4秒 |
| 拨匀炭火 | 按住火钳，将两处堆积的炭火向炉内空处拨开 | 火钳跟手，炭粒移动，局部火光逐渐均匀。走过两条较宽的引导区域即完成 | 3—5秒 |
| 收茶回筛、回凉 | 将竹筛拖到接茶位置，接好茶后再移到桌边回凉垫上 | 接茶轮廓吸附、茶叶落筛，桌边落位后热气渐弱，再显示复焙结果。中间接茶只需短停留 | 4—6秒 |
| 铺好衬料 | 将衬纸拖入箱口，自动展开；再沿提示方向抹平一次 | 衬纸贴合箱底、纸角落下，抹过区域变平。落位并完成一次宽幅抹平后进入装茶 | 4—5秒 |
| 装入茶货 | 将茶篓拖到箱口上方并停住约1秒 | 茶篓自动倾斜，茶叶落入箱中，填充高度升至标线后自动停。松手收回茶篓，进入合盖 | 3—4秒 |

### 关键区别

- **摊叶**是大幅向外拨开；**捻叶**是小幅往返。动作范围通过放大的茶样和方向示意区分。
- **拨火**在炉内横向拨动；已有的**翻茶**沿盘面绕圈；**回凉**是从炉边移到桌边，三步有不同空间和节奏。
- **铺衬**表现展开与抹平；**装茶**表现悬停倾倒；已有的**封绳**表现沿路描画，避免三个包装步骤都成为拖物到框里。
- 干湿观察属于视觉模拟，普通触摸屏不感知捏力。无需双指捏合、压力传感器或快速揉搓。

## 3. 给封绳补一个合盖动作

在描绳前，把桌边箱盖拖到箱口轮廓中，接近后吸附；松手播放短促的落盖反馈，然后直接亮起现有的第一道绳路。

- 目标增加约2秒，合盖与封绳共用当前包装工序，不再增加确认页面。
- 箱盖不要求旋转，落位范围比轮廓略大，适合手指遮挡时判断。
- 完成两道绳之前，整道「合盖扎绳」工序不提交；恢复弹窗后保留已合盖状态。

## 4. 取工具与提示统一

当前部分步骤是「点击取工具 → 再点场景操作 → 观看／执行动作」。建议改为：

**按住工具或材料 → 拖向操作区 → 直接执行这道工序。**

- 火钳、竹筛、衬纸、茶篓、箱盖在工具盘中直接可抓取；阶段内只突出当前能用的一件。
- 为减少触摸屏上的长距离伸手，工具就位后在工作台附近继续操作，不必每一步都从屏幕最底部重新抓取。
- 保留轻触取工具的宽容入口：轻触后工具移到工作台边，游客可以就近抓住操作。
- 工作区始终只有一条短提示，例如「把茶篓移到箱口，停一停」；首次闲置数秒播放一次手势示意，触摸立即隐藏。
- 到位采用吸附、描边变化和简短对白共同反馈。没有音效也能看懂；关闭声音设置后不强制发声。

## 5. 交接与航行：第二批可选补充

先实现六道工序和合盖，再根据完整一局的时长决定是否增加以下动作。它们替换既有交接按钮或为已选决策补演出，不增加多余的反复确认。

| 环节 | 简单手势 | 触发与规则 |
|---|---|---|
| 采购成交后接货单 | 将梁老板递出的货单拖到自己的账本上 | 出现在议价结果之后；采购已记账，不因拖动再次付款。纸单落位后显示实付与等待天数 |
| 风雨中临时加篷 | 拉住篷布边缘，横向滑过茶箱 | 先明确选择并确认原有加篷费用，再执行动作。篷布展开、雨水沿边缘滑落；保护效果沿用该选项规则 |
| 船板渗水时补漏 | 把补漏材料拖到渗水位置，按住片刻 | 只在玩家选择补漏后出现。动作表现这次应对，不保证整段航程零损失 |
| 交货后收回单 | 将交接人递来的回单拖入账本 | 显示实际到货、货色与实收；沿用当前结算结果，不重复结算 |

订单选择、货源比较、还价、火候方案、包装方案、驳运路线及亏损时的处置继续用清楚的点击选项。这些地方需要先读清成本与后果，手势适合放在决定之后的实际工序与交接处。

## 6. 完成、容错与信息规则

1. **不考手速。** 慢慢拖也能完成；不要求猛划、连点、精细旋转或双指配合。倾倒依赖到位停留，不依赖快划产生的惯性。
2. **有效进度可保留。** 松手不会清空已观察区域、已铺好的纸或已装入的茶；离开目标区域暂停倾倒，返回继续。箱盖或工具放偏回到安全位置。
3. **操作失误不额外扣币和天数。** 费用与游戏天数沿用已确认的经营选择；重试不会重抽随机结果。
4. **完成才提交，且只提交一次。** 使用现有阶段与版本校验；弹窗、失焦或触摸取消解除抓取，返回后重新按住继续。
5. **线索与验货深度一致。** 摊叶、捻叶表现读取现有 `inspection_clue()`，不新建与数值矛盾的好坏结果。抽样阶段仍只给观察线索，汇总显示货色区间；复核完成才显示准确货色。
6. **经营选择仍有后果。** 拨火顺利不抹去火候方案差异，装茶整齐不改变已经选择的包装保护，完成加篷也不把运输风险强行归零。
7. **适配单机节奏。** 重复复焙时仍保留动作，但省去重复教学；抽样无需强迫观察全部三项，不复焙的路线无需额外加入焙茶操作。

## 7. 素材与实现范围

- 优先复用现有火钳、竹筛、衬料、茶篓、箱盖及场景。茶叶散开、炭粒、纸角、填充高度、热气和轮廓由Godot实时绘制。
- 需要补图时，优先用ImageGen制作可独立移动的茶叶近景、筛内茶叶、侧倾茶篓与篷布；确认工序动作后再生成，不提前改写背景原图。
- 这些动作是游戏化工序表达；具体器具、材料与历史细节延续馆方审定流程。
- 扩展现有手势层，保留经营模型。新增复合动作只增加工序内部进度，不拆出重复收费的经营步骤。

## 8. 推荐实施顺序与验收

**第一批：**补齐六道工序，加上合盖，并统一取工具的衔接。完整流程形成「拨开—轻捻—晃杯—拨火—绕盘—移筛—铺纸—倾倒—合盖—描绳—拖箱」。

**第二批：**优先选择最能改善体验的交接或天气动作；按首次游玩耗时决定是否全部加入，目标仍为3—5分钟。

实现后的检查重点：

- 鼠标与原生单指触摸均能完成，宽范围操作与短停留在30帧兼容模式下有效。
- 检查快速划过、停在原处、放错位置、半途松手、第二根手指、弹窗与失焦；能恢复，不能重复扣款或跳过工序。
- 同一种子、同样经营策略在改动前后的钱、天数、货色、运输结果与结算保持一致。
- 画面核对手指遮挡、路径对比度、工具范围以及材料是否跟随轨迹；每步能看到明确的完成反馈。
- 至少走完一条不复焙路线和一条复焙路线，记录教学、对话、手势与总用时，避免为了操作数量拉长全局。
