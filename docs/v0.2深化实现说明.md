# v0.2 深化实现说明

日期：2026-09-15\
项目：广东省博物馆十三行互动经营游戏\
工作名：**十三行 · 茶船将发**\
引擎：Godot 4.7.2；画布：1920×1080横屏；目标单局：3–5分钟。

## 1. 本轮范围

针对“文字多、场景少、没有人物剧情、结果固定”的反馈，已经把茶叶订单重做为场景中的短篇经营。保留短时展厅体验目标，以一笔完整交易呈现经营，而不是增加大量说明页。

本轮实现四场景、四角色、八个新增ImageGen素材、七组经营决策、三类随机遭遇、装箱互动、盈亏结算，以及数字分身替换接口。

这是可运行的深化原型；自由漫游、多日商铺经营、完整角色骨骼动画、真人分身生成端和配音尚未实现。

## 2. 故事与人物

**主线：**新任采购管事第一次独立照应茶单。陈叔把账本交给玩家；玩家在梁老板处选货议价，决定如何验货与整理，在货栈与陈叔封箱，再交给阿顺驳运。江上的变化打乱原先盘算，最终回行号结账。

| 角色 | 作用 | 已实现 |
|---|---|---|
| 玩家·阿砚 | 作出所有经营决策；未来由游客数字分身代入 | 独立全身透明PNG、移动／呼吸、名称替换 |
| 陈叔·老管事 | 开场托付、装箱指导、盈亏收尾 | 独立立绘、短对白、按盈亏变化的结尾 |
| 梁老板·茶商 | 报价、供应与议价 | 独立立绘；议价成功／失败反馈 |
| 阿顺·船家 | 航线选择与临场应对 | 独立立绘；风雨、渗水、平稳三个事件分支 |

人物均为虚构。玩家定位暂用“行号采购管事”，不把买办、行商、独立店主的职责混为一谈；正式称谓由馆方审核。

## 3. 场景与动作

| 场景 | 经营内容 | 动态表现 |
|---|---|---|
| 行号账房 | 陈叔托付、选单、结账与收尾 | 玩家入场、人物呼吸、浮尘、短对白 |
| 茶市 | 三处货源、议价、验茶、整理决定 | 换景、人物出场、茶样观察入口 |
| 装箱间 | 三种包装，三步操作 | 人物走近茶箱、纸料与茶叶落入、完成后转场 |
| 江岸码头 | 三种航线、随机事件及应对 | 水纹、风雨粒子、茶箱搬往艇上 |

场景背景与人物分层。人物没有烘焙在背景里，数字分身替换不会要求重新生成场景。

目前动作以精灵位移、缩放和程序粒子实现，尚非逐帧动画或骨骼动作。两张开／合茶箱承担状态表达，封箱是工序互动示意，尚不是精细物理装载。

## 4. 单局流程与节奏

```mermaid
flowchart LR
 A[账房接过任务] --> B[选择茶单]
 B --> C[茶市选货与议价]
 C --> D[验货与处理]
 D --> E[装箱间选择包装]
 E --> F[衬料／装茶／扎绳]
 F --> G[码头选择航线]
 G --> H{江上随机遭遇}
 H --> I[避风／抢行／加篷等应对]
 I --> J[实际交验与结算]
 J --> K[回到行号收尾]
```

主要经营决策约8次，另有开场回应、装箱触点和收尾。对白可逐字呈现，也能点“全文”立即展开；选择不会被强制对白等待拦住。

建议观察目标：开场与选单30–45秒，茶市60–90秒，装箱35–50秒，码头与事件35–55秒，结算25–40秒。合计仅是设计预算，不能代替真实游客测试。

## 5. 已实现的经营选择

| 环节 | 可选策略 | 主要代价 |
|---|---|---|
| 订单 | 稳妥／赶船／上等 | 单价、交期、货色门槛、迟交罚款不同 |
| 货源 | 远仓／街坊／精拣 | 报价、工期、正常货色范围和劣批概率不同 |
| 议价 | 照价／温和／坚持 | 成功省钱；失败照价成交且多耗1或2格 |
| 验货 | 凭样／抽样／逐箱 | 0／8／18点与0／1／2格，换取不同程度的信息 |
| 处理 | 照货／复焙／换货 | 不加支出，或20点加12货色、34点加24货色，处理均耗2格 |
| 包装 | 草衬／双层／加固 | 8／20／35点；耗1／1／2格，保护系数不同 |
| 航线 | 合运／专艇／沿岸 | 10／24／17点；耗2／1／3格，风险暴露不同 |
| 临场 | 按事件出现2–3种选项 | 钱、工期与损货概率继续取舍 |

货色上限100。货色是一种教学用综合指标；不是历史上实际采用的评分方法。

每次扣钱前检查预算，为最低装箱与船费保留空间。没有钱也能在江上选择无额外费用的应对。亏掉本金时，退款差额可能使最终资金为负，代表本单欠款。

## 6. 随机系统

随机数由独立交易模型持有。正常开局使用新种子；测试可以指定种子复现。环境粒子使用另一随机源，开帮助、看账本、截图、角色动画均不会改变生意运气。

### 随机抽取时机

| 随机量 | 抽取时机 | 影响 |
|---|---|---|
| 出门时天气预报 | 开局 | 江上风雨事件的发生概率 |
| 三处报价 | 开局 | 基价的92%–110%，四舍五入 |
| 议价成功 | 确认议价时 | 温和70%省8%，坚持35%省18%；失败耗时 |
| 货色与劣批 | 采购成交时 | 货源正常范围内抽取，另按货源概率降低15–30 |
| 江上事件 | 支付船费时 | 风雨、渗水或平稳 |
| 是否损货、损失箱数 | 确认应对时 | 发生时损坏2–5箱 |
| 到货货色变化 | 应对结算时 | 正常减0–3；损货遭遇另减10–26 |

“正常货色范围”不是质量保证，劣批仍可能落到范围以下。抽样显示实际货色±7的估计区间；逐箱复核显示准确值。整改后的信息保持与验货方式相符。

### 风险公式

`损货概率 = 事件强度 × 航线暴露 × (1 − 包装保护) × 应对系数`

最终限制在1%–95%。界面显示四舍五入后的概率；不能把95%理解为必然损坏，1%也不等于绝对安全。

- 风雨强度0.85；渗水0.65；平稳0.15。
- 航线暴露：合运1.20，专艇0.75，沿岸0.45。
- 包装保护：草衬0.12，双层0.50，加固0.82。
- 风雨应对：避风0.35／多2格；抢行1.0；加篷0.18／12点且多1格。
- 渗水应对：补漏0.25／12点且多1格；继续赶路1.0。
- 平稳交接：雇帮手0.8／8点且省1格；正常交接1.0。

预报晴、欲雨、风雨将至，对应风雨事件18%、45%、68%；渗水额外16%，剩余概率平稳。因此预报晴也可能突遇风雨。

所有概率是当前玩法参数，没有冒充历史统计。

## 7. 收款与亏损

```text
合格交付箱数 = 10 − 损货箱数
货色折价系数 = clamp(1 − max(0, 要求货色 − 到货货色) × 0.018, 0.25, 1)
交货货值 = round(交付箱数 × 订单单价 × 折价系数)
迟交扣款 = 超期格数 × 该订单每格罚款
实际货款 = max(0, 交货货值 − 迟交扣款)
尾款或退款 = 实际货款 − 已收预付60点
本单利润 = 实际货款 − 所有经营支出
最终资金 = 初始本金160点 + 本单利润
```

预付不是额外奖励。实际货款低于60点，会退回多收部分。结果页将实际货款、尾款／退款分开显示；账本保存逐笔收支和余额。

种子9的测试案例：赶船单、远仓、强议价、不验货、不整理、草衬、合运、风雨中抢行。实际交付6箱、货色21、迟交1格，货款20点、支出120点，亏100点。它是随机模型的一次可复现样本，不是正常游玩的指定失败结局。

## 8. 数字分身接口

### 已实现

默认配置：`prototype/data/avatar_profile.json`。运行入口：

```gdscript
var accepted = main.set_player_profile({
    "id": "session_avatar",
    "display_name": "小粤",
    "body_texture": "user://avatars/current_body.png",
    "height": 610,
    "source_foot": [0.5, 0.96],
    "tint": "ffffff",
    "is_fictional": false
})
```

- 支持 `res://` 已导入纹理，以及 `user://` 运行时PNG。
- 字段 `height` 控制角色画布高度，`source_foot` 为图内归一化脚底锚点。
- 显示名最多8字，角色替换失败返回false，当前形象保持。
- 玩家经济、剧情与外观分离；替换不改现金、工期和随机状态。
- 正常结束／空闲复位恢复默认角色；同一局后的“再做一单”保留当前游客形象。
- 日志不记录头像、照片、显示名和人物文件路径。
- `portrait_texture` 是预留字段，本轮界面未消费它。
- 运行时图片检查不超过4096×4096；仅支持2D纹理，不是3D模型或任意骨骼输入。

### 尚需制作

1. 数字分身生成端：获取游客已同意使用的形象，输出统一尺寸、透明背景、脚底锚点与角色风格。
2. 生成等待／失败回退：完成前可选默认化身开始；不让现场体验无限等待。
3. 会话映射：只把当前游客的临时资源传给当前游戏实例。
4. 图片生命周期：游戏端已清空当前引用；生成端尚需负责临时文件的清理与保留策略。
5. 面部表情、口型、服装与动作：后续可把Actor替换为分层精灵或骨骼场景，交易模型保持不变。
6. 馆方确认图像授权、生成流程、现场隐私提示及人工回退方式。

本轮没有采集照片、访问摄像头或连接人脸生成服务。

## 9. 工程结构

| 文件 | 职责 |
|---|---|
| `scripts/trade_session.gd` | 状态、随机、预算、账本与结算 |
| `data/trade_v2.json` | 订单、供应、包装和航线参数 |
| `scripts/main.gd` | 场景布置、对白、选项、触摸、复位 |
| `scripts/actor.gd` | 全身像加载、脚底锚点、呼吸和移动 |
| `scripts/atmosphere.gd` | 雨丝、水纹、浮尘 |
| `scripts/packing_effect.gd` | 装箱时的衬料与落茶 |
| `scripts/touch_button.gd` | 原生触摸的抬手激活 |
| `scripts/session_log.gd` | 匿名本地事件日志与大小轮换 |

当前主场景为代码构建。进入正式批量制作前，建议将对白／场景调度拆入独立资源，并将各场景保存为编辑器可布置的.tscn，让美术与策划能独立调整。该拆分尚未完成，不影响当前可玩流程。

## 10. 测试与验收

自动测试覆盖资金与货物守恒、预付抵扣、退款、非法输入、过期按钮、预算不足、相同种子重现、相同策略不同盈亏、风险改善、全量复位、运行时角色图片、触摸模态与文本边界。

下一轮真人重点记录：

- 不经解释能否理解三种茶单和角色职责。
- 玩家是否在低价、验货与船期之间作有意识的取舍。
- 装箱是否像在做事，还是仍像连续点按钮。
- 亏损后能否说出至少一个原因。
- 是否能在3–5分钟内完成，并记住一个贸易分工知识点。
- 角色大小、触点物理尺寸、屏幕倾角与文字可读性。

## 11. 后续制作顺序

1. **先评体验**：真实横屏与8–12位游客观察，调整文本、停留与盈亏分布。
2. **再细化表演**：陈叔、茶商、船家的表情与动作；真正的合盖扎绳、搬货装船序列。
3. **接数字分身**：贯通生成、排队、替换、异常回退、离场清理。
4. **扩商品机制**：瓷器重破损与装载，丝绸重样式规格、染色与交付；避免只换图与文字。
5. **正式部署**：目标硬件性能、触摸系统、自启守护、离线包、长时间运行与馆方审校。

时间与预算需在现场测试和分身生成方案确定后重估；原可行性计划的估算不能自动视作新增功能的固定报价。
