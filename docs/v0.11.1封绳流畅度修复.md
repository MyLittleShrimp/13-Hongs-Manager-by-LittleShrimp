# v0.11.1 封绳流畅度修复

## 已复现的问题

旧版封绳将绳路分为约16像素的小段，依次命中后才更新可见绳头；看起来像跳格子。下一个小段要求离指针不超过25像素，偏移稍大就会停止推进。封箱绘制层还每帧重建纸衬、茶叶、箱盖和54条木纹，即使这些内容没有变化。

在本机用同一组确定性轨迹对比，坐标均为1920×1080设计空间：

| 检查 | v0.11.0 | v0.11.1 |
| --- | --- | --- |
| 连续120次、每次1像素直线移动 | 绳头111次不动，最大跳动15.33像素 | 绳头每次前进，最大移动1.00像素 |
| 沿首段平行偏移30像素，前进240像素 | 未推进 | 连续推进240像素 |
| 箱盖静止，30帧Compatibility下观察60帧 | 重建绘制60次 | 重建绘制0次，复用已有绘制指令 |

数据用于说明输入及绘制机制的变化，不代表其他设备的帧率或触控延迟测试。

## 实现

1. 以沿绳路的连续距离记录进度，计算指针在附近绳段上的投影。绳头与进度条使用同一距离，不再等候下一个离散路点。
2. 允许36像素绳路容差，续画抓取范围48像素。每次只允许在已完成进度前后64像素范围内接续，避免远处重入直接跳过绳路。
3. 稀疏移动事件最多每8像素检查一次，中间路径仍须经过合理范围；每个事件最多256个检查点，极端坐标也不会产生无界循环。
4. 末端剩余不超过12像素且指针仍在终点36像素内时收齐。完成仍需松手，两道绳各自结算；同位置点击不会推进。
5. 静态箱盖层仅在绘制状态改变时调用`queue_redraw()`。独立绳层照常响应输入；铺衬、倒茶、落盖等变化继续更新。

保留单指归属、Windows混合事件去重、暂停／失焦取消抓取、部分进度保存和一次提交保护。没有修改经营模型、费用、天数、货色、概率或结算。

## 验证范围

- `test_rope_smoothness.gd`通过实际游戏视口注入鼠标／原生触摸事件，覆盖1像素慢划、±30像素平行偏移、稀疏快划、圆角、松手续画、弹窗和失焦。
- 检查重复点击、端点跳过、离路绕行、双指与取消触摸；完成后核对资金、天数、货色、随机状态和账本没有额外变化。
- 实际GPU检查封箱静止60帧不重建，描绳独立更新，倒茶连续10个变化状态均重绘。
- 发布脚本从最终ZIP重新解压，运行原有手势、七动作、音乐、兼容、剧情与完整交易验证；同时运行1280×720、30帧Compatibility专项。

本机为NVIDIA显卡，原Snapdragon 860设备尚未实机回测。相关日志随本次构建保留在`output/releases/v0.11.1`。
