# v0.11 工序手势与操作衔接

已实现经用户确认的第一批：六道工序、七个动作，以及取工具到操作的衔接。航行加篷、补漏与交接单据等第二批提案尚未加入。

## 玩法

| 步骤 | 操作与完成条件 | 可恢复的进度 |
|---|---|---|
| 看叶形 | 从茶样中央向两侧拨开，松手记录 | 已摊开的方向保留 |
| 辨干湿 | 按住茶样，短距离往返两回，松手记录 | 已完成次数保留；抖动或分开点按不算轻捻 |
| 拨火 | 火钳从中间向两侧拨匀，松手收钳 | 已拨开的一侧保留 |
| 收茶回凉 | 竹筛在接茶处停约0.4秒，移到回凉小台后松手 | 已接到筛里的茶保留；回凉反馈结束才增加原有货色提升 |
| 铺衬 | 衬料拖到箱口后松手展开，再从亮点抹平 | 展开状态和抹平进度保留 |
| 装茶 | 茶篓移到箱口上方，按住约1.1秒，装满后松手 | 已倒入的茶保留；移开、松手、弹窗或失焦均暂停倾倒 |
| 合盖 | 箱盖拖到箱口，对齐后松手，直接开始描绳 | 合盖状态保留；两道绳完成后才提交整道封箱工序 |

查看茶样只给既有观察线索。抽样仍在汇总时给范围，复核才给准确货色；手势不新增不同的好坏判定。未选择复焙的生意无需执行焙茶工序。

## 操作衔接

- 工具盘中当前道具可直接按住拖到工作区，原始按下事件连续交给工序处理，无需松手再点一次开始。
- 轻触取工具也有效：工具停到操作区附近，再抓住便能继续。工作页面隐藏多余的开始按钮。
- 顶部短句随工序内部阶段更新，画面显示目标轮廓、亮点、装填变化与工具跟随。首次停留后有简短方向示意，操作后隐藏。
- 旧版Windows触摸附带鼠标事件仍通过同一输入保护处理；第二根手指不能接管当前工序。

## 容错与规则

- 只认有效轨迹、目标位置和必要的短停留，不设操作倒计时，不考手速。
- 放错可重试；点击终点、悬停不按、抖动、窗口失焦后的松手不能自动过关。
- 弹窗暂停并解除抓取，返回后从保留的有效进度继续；退出本局取消所有待提交动作。
- 原有阶段与版本校验保证每道工序只提交一次。费用与时间仍由经营选择决定，不因重试增加，不重抽随机结果。

## 实现与素材

- `craft_gestures.gd`继承现有`gesture_workshop.gd`，复用单指归属、松手提交与原有四类手势。
- `main.gd`连接工具盘的原始输入、轻触入口、短提示和工序进度；`packing_effect.gd`由实际铺纸／倒茶／合盖进度驱动画面。
- 本轮复用现有ImageGen工具图集、茶箱、场景和人物。茶样近看托盘、炭粒、回凉小台、茶叶、箱盖与引导由Godot绘制，没有改写原始图片。
- 素材数量维持31张ImageGen PNG、4张历史参考JPEG及两首MP3。道具与工序属于游戏化表达，具体历史内容仍待馆方审定。

## 验证

- 新增`test_craft_gestures.gd`，以真实视口鼠标／原生触摸事件执行七个动作；基础专项218项检查通过。
- 含复焙和不复焙的两条完整交易，双主角分别完成；逐步与原经营模型对照，钱、天数、货色、随机状态、账本及最终结算一致。
- UI与既有工序／手势回归通过；3,000局经营回归仍为1,947盈利、1,046亏损、7持平。固定测试策略的分布不是游客胜率预测。
- 实际GPU、1920×1080、30帧Compatibility模式检查动作与画面，截图保存在`artifacts/v0.11/screens/`。
- 构建工具从干净提交打包，再重新解压执行全部发布专项，另以1280×720、30帧运行完整工序交易；日志与哈希写入`output/releases/v0.11.0/`。

单局3—5分钟是设计目标；自动化测试用时不代表首次游客用时。真实触摸硬件与数字分身仍按用户安排后置。
